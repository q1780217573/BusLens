# BusLens 使用说明书

> CAN / CAN FD 总线分析与诊断工具
>
> 英文名 BusLens ｜ 品牌名 CANova ｜ 中文名 观澜
>
> 版本 v3.2.1 ｜ 2026-11-24 ｜ 适用 Windows 10 / 11（64 位）

---

## 一、软件概述

BusLens 是一款面向汽车电子测试的 CAN 总线工具，把日常排查中分散的几件事收在一个界面里：

- **DBC 报文解析** —— 按 DBC 定义把原始字节还原成信号物理值
- **总线实时监控** —— 接收、聚合统计、逐帧流水
- **报文发送** —— 按 DBC 信号组帧发送，或直接发原始帧
- **数据回放** —— 把录制的日志按时间轴重新送上总线
- **UDS 诊断** —— ISO-TP 分包收发，常用诊断服务图形化
- **日志格式转换** —— TRC / ASC / BLF 互转

设计上对标图莫斯 TCANLINPro 与 PCAN-View，但保持单文件绿色运行：**不需要安装，不写注册表，不装驱动**（PCAN 驱动需系统已装好，见第四章）。

## 二、运行环境

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11，64 位 |
| 硬件驱动 | PEAK PCAN 驱动（使用 PCAN 硬件时必需，随硬件安装） |
| 其他依赖 | 无。PCANBasic.dll 已内嵌在 exe 中 |
| 权限 | **普通权限即可，不要用管理员运行**（原因见 8.1） |
| 磁盘占用 | 约 30 MB（单文件） |

### 安装与启动

1. 把 `BusLens.exe` 复制到任意目录（建议 D 盘，避开 `Program Files`）
2. 双击 `BusLens.exe` 启动
3. 也可以双击随附的 `启动 BusLens.bat`

首次启动会自动加载上次使用的 DBC；没有记录时 DBC 区域为空白。

## 四、解析页

解析页把「选 DBC → 导入日志 → 解析报文」放在同一页完成，不需要来回切页。

### 4.1 加载 DBC

三种方式任选：

1. 点「浏览」选择 `.dbc` 文件
2. 把文件**拖进窗口任意位置**（自动识别类型）
3. 在路径框输入路径后按回车

加载成功后，左栏会列出全部报文，状态栏显示「已加载 N 条报文」。

点「示例」会加载上次使用过的 DBC，用于快速回到上次的工作状态。

### 4.2 报文列表

左栏是树形结构：**报文为父节点，信号为子节点**。

| 列 | 内容 |
|---|---|
| ID | 报文 ID（十六进制） |
| 报文 / 信号 | 报文名；展开后是信号名（浅灰显示） |
| 信号 | 报文行显示信号数量；信号行显示单位 |

操作方式：

- **点报文前的三角** 展开，直接看到该报文下的全部信号名
- **双击报文行** 切换展开 / 折叠
- **展开全部 / 折叠全部** 一次铺开或收起
- **点选报文或信号**，右侧单帧解析区自动带出该报文的 ID；选中信号时，若它已在解析结果里，会同步选中并滚进视野

顶部搜索框支持三类关键词，任一命中即列出：

| 输入 | 结果 |
|---|---|
| `0x203` / `515` | 命中该报文，折叠 |
| 报文名片段，如 `cdcu` | 命中报文，带全部信号，折叠 |
| 信号名片段，如 `tja114` | 列出**所属报文**并自动展开，只显示命中的信号 |

命中时状态栏给出统计：`搜索「tja114」— 报文 2 个，信号命中 4 条`。

信号名太长显示不全时，把左栏往右拖即可（见 4.5）。

### 4.3 单帧解析

在号区域输入两样东西：

| 字段 | 格式 | 说明 |
|---|---|---|
| ID | `0x214` 或 `532` | 带 0x 按十六进制，不带按十进制 |
| 数据 | `E8 03 DC 05` 或 `112233` | 空格可有可无 |

点「解析」（或按回车），下方结果表列出全部信号：

- **信号名 / 值 / 单位 / 注释**
- 有值表（Value Table）的信号会附带枚举含义，例如 `[On]`
- 多路复用信号会按当前 mux 值自动过滤，只显示有效信号

「粘贴」按钮会尝试从剪贴板识别「ID + 数据」或纯数据。

### 4.4 日志导入

支持的格式：`.trc` `.asc` `.blf` `.txt` `.log` `.hex` `.dat` `.csv`

- 点「从文件导入」选择文件，或直接把文件拖入窗口
- 导入后记录逐行列出：`#` / `时间(s)` / `ID` / `扩展` / `DLC` / `数据`
- **双击任意记录行** → 弹出独立窗口解析该帧的全部信号，可同时打开多个对照

ASC 格式同时支持两种写法：

```
0.001000 1  214#E803DC0500000000                                  ← 精简格式
0.001000 1  214  Rx  d 8  E8 03 DC 05 00 00 00 00                 ← PCAN/CANoe 常规导出
```

### 4.5 调整分栏

左栏与右侧之间、右侧的上下两块之间，都有可拖拽的分隔条：

- 拖动分隔条调整占比，**松手即自动保存**到 `%LOCALAPPDATA%\BusLens\config.json`
- 左栏拉宽时「报文 / 信号」列跟着变宽，长信号名能看全
- 下次启动按上次的位置恢复

拖乱了，点左栏上方的 **「复位布局」**：分栏与窗口尺寸一起回到默认，并清掉这一页的存档。

「实时」页打开的发送、普通发送、UDS 诊断窗口同样支持拖动与复位，各自独立记忆，互不影响。

## 六、监控页

### 6.1 通道配置

点「通道配置」打开对话框。**点「确定」后会自动连接通道**，不需要再点一次「连接」。

| 参数 | 说明 |
|---|---|
| 通道 | 枚举到的 PCAN 通道，显示状态（空闲 / 已被占用 / 正在使用） |
| 帧格式 | 经典 CAN / CAN FD |
| 时钟 | 仅 CAN FD 有意义（20 / 24 / 30 / 40 / 60 / 80 MHz） |
| 仲裁段 | 波特率、采样点、SJW |
| 数据段 | 仅 CAN FD：数据波特率、采样点、SJW |
| 手动 BRP/SEG | 勾选后直接指定 brp / tseg1 / tseg2，覆盖自动反算 |
| DBC | 可为本页单独指定 DBC，留空则沿用主界面的 |
| 收发模式 | **正常收发** / 只监听 |

**关于位定时，有两点必须知道：**

1. **经典 CAN 的硬件时钟固定为 8 MHz**，界面上的 80/40 MHz 只对 CAN FD 生效。这是 PCAN 驱动的限制，不是软件问题。
2. 8 MHz 下算不出接近目标的采样点时会自动退回标准 BTR（500k 即 87.5%），此时实际采样点会偏离你填的值，界面上会标注实际值。

### 6.2 只监听模式

勾选「只监听」后通道以被动状态打开：不发 ACK、不发帧，对总线零影响。适合旁路观察其他设备通信。

只监听模式下**不能发送**，发送窗口会提示。

### 6.3 监控视图

工具条按钮：`通道配置` `连接` `录制` `发送` `暂停` `清空`

两种视图可切换：

**聚合视图** —— 按 ID 归并，一行一条报文

| 列 | 含义 |
|---|---|
| ID | 报文 ID |
| 报文名称 | 来自 DBC |
| DLC | 数据长度 |
| 周期 ms | 实测周期，滑动平均 |
| 计数 | 累计帧数 |
| 变化 | 数据变动的次数 |

选中一行后，右侧显示该报文的最新信号值：

- 信号名 / 原始值 / 物理值 / 单位
- **上方另有一条原始字节条**，完整显示最近一帧的全部字节（CAN FD 64 字节也不截断），可直接选中复制，用于核对解析是否正确

**逐帧视图** —— 按到达顺序逐帧流水，列：`序号` / `时间戳` / `方向` / `ID` / `长度` / `数据` / `帧类型` / `帧格式`

### 6.4 录制

点「录制」选择保存路径，支持 `.trc` / `.asc` / `.blf` / `.csv`。再次点击停止。

录制的文件可以直接用本工具的「转换」「回放」功能处理。

### 6.5 发送

点「发送」弹出菜单，四项：

| 菜单项 | 说明 |
|---|---|
| **DBC 发送（信号）** | 按 DBC 信号组帧，改信号值即可，见 6.6 |
| **普通发送（原始帧）** | 不依赖 DBC，直接填 ID 与字节 |
| **数据回放** | 把日志文件重放到总线，见 6.7 |
| **CAN UDS 诊断** | 见第七章 |

所有发送窗口都复用监控页已连接的通道——PCAN 通道是独占的，另开必然失败。

### 6.6 DBC 发送窗口

界面分三栏：

- **左：消息列表** —— 双击或右键加入发送列表
- **右上：发送列表** —— `启用` / `消息名称` / `ID` / `DLC` / `原始数据(Hex)` / `间隔(ms)` / `已发`
- **右下：信号表** —— 选中一条报文后列出它的全部信号

**操作要点：**

- 「启用」格**单击**即切换，不用双击
- 双击「间隔」可改发送周期
- 双击信号表的「实际值」就地编辑，改完整行原始数据立刻重算
- 信号值超出 DBC 定义的 min/max 会自动钳位并提示
- 顶部「发送次数」+「循环发送」，模式可选「并行发送」（每行按自己间隔）或「顺序发送」（按列表顺序轮转）
- 「列表操作」可把整份发送列表导出成 CSV，或从 CSV 读回
- UDS 刷写整包时用「载入文件」直接喂给 0x36 传输，见 7.3

> 发送完成后，列表里的勾选状态**不会**被清掉——勾选只代表你的意图，发够次数由「已发」列体现。

### 6.7 数据回放

选择日志文件（TRC / ASC / BLF）后：

- 按原时间戳重放到总线，可设**速度倍率**
- 支持**循环回放**、暂停 / 继续
- 通道同样复用监控页已打开的那个

## 七、UDS 诊断

### 7.1 基本设置

| 字段 | 说明 |
|---|---|
| 物理地址 | 单 ECU 诊断请求 ID，默认 `704` |
| 功能地址 | 广播地址，默认 `7DF` |
| 响应地址 | 期望的响应 ID，默认 `705` |
| 超时 ms | 单次请求等待时间，默认 1000 |
| 地址模式 | 物理地址 / 功能地址切换 |

选「功能地址」时，一次广播会收集**窗口内所有 ECU 的应答**，逐条记录，适合探测总线上有哪些节点在线。

### 7.2 支持的诊断服务

共 27 个服务，按四组排列：

**会话与安全**
`10` 诊断会话控制 · `11` ECU 重置 · `27` 安全访问 · `29` 认证 · `3E` 待机握手 · `28` 通讯控制 · `83` 访问计时参数 · `85` 控制 DTC 设置

**数据读写**
`22` 按标识符读数据 · `2E` 按标识符写数据 · `2F` IO 控制 · `2A` 周期读取 · `24` 读缩放信息 · `2C` 动态定义数据标识 · `23` 读内存 · `3D` 写内存

**DTC**
`14` 清除诊断信息 · `19` 读取 DTC 信息 · `86` 基于事件响应

**例程与传输**
`31` 例程控制 · `34` 请求下载 · `35` 请求上传 · `36` 传输数据 · `37` 传输退出 · `38` 文件传输 · `84` 受保护数据 · `87` 链路控制

`19` 支持 12 种子功能（01/02/03/04/06/0A/0B/0C/0D/0E/0F/10）。

### 7.3 常用流程

**读版本号**

1. `10 03` 进扩展会话
2. `22 F1 90` 读 DID
3. 日志区显示响应与解析结果

**读故障码**

1. `19 02 FF` 读全部 DTC
2. 日志区自动解析成 `P0123 status=0x08 confirmedDTC` 并列出状态位

**刷写（34 → 36 → 37）**

1. `34` 请求下载，填地址与总长度
2. 执行后状态栏显示 ECU 返回的**最大块长**
3. 切到 `36`，可以：
   - 在「数据」里粘贴 hex，程序按块长自动切分发送
   - 或点「载入文件」，选择 `.bin` / `.hex` 整包，程序按块长自动分块
4. `37` 传输退出

块序号（BSC）从 1 自动递增到 255 后回到 1，无需手工维护。

### 7.4 安全访问（0x27）注意事项

`0x27` 的 Key 算法是**厂商私有**，本工具默认填的是示例算法：

```python
bytes([(b ^ 0x5A) for b in seed])
```

拿不到真实算法时，请求种子能成功，但发送 Key 会返回 `7F 27 35`（密钥无效）——**这是正常现象，不是软件故障**。

拿到算法后填进「Key 算法(Python)」输入框即可，支持任意 Python 表达式，环境里提供 `seed`（bytes）与 `bytes`/`bytearray`，例如：

```python
bytes([(b + 0x33) & 0xFF for b in seed])
```

### 7.5 其他

- 勾选「保活 3E」后每 2 秒自动握手，防止会话超时
- 收到 `7F xx 78`（响应挂起）时会自动延长等待，最多 5 轮
- 支持批量列表：把多条请求加入列表，设置延时后循环执行，并统计通过率
- 日志可导出为 txt，或开启「实时保存」边测边写
- CAN FD 通道下 ISO-TP 自动切换：单帧最多 62 字节，连续帧每帧 63 字节

## 八、常见问题

### 8.1 拖文件进窗口显示禁止光标，松手没反应

**原因**：程序以管理员权限运行。Windows 的 UIPI 隔离会阻止普通程序（资源管理器）向高权限进程拖放。

**解决**：关掉窗口，从资源管理器**双击** `BusLens.exe` 启动，不要右键「以管理员身份运行」。正常时状态栏右下角显示绿色「拖拽就绪」。

如果双击后仍不行，点状态栏右下角看诊断弹窗。

### 8.2 通道已被占用，连不上

PCAN 通道被一个程序独占。常见占用者：

- **Testflow 等本类程序** —— 无法共享，必须先关掉对方
- **PCAN-View** —— 可以用「只监听 + 波特率自适应」只读接入，但仍不能发送

程序检测到占用会提示，并说明占用者类型。

### 8.3 通道状态显示「正在使用（本程序）」

这不是冲突。改完通道配置点「确定」会自动重连，不需要先断开。

### 8.4 经典 CAN 设了 80 MHz 却没生效

经典 CAN 的 PCAN 驱动时钟固定 8 MHz，80/40 MHz 只对 CAN FD 有效。程序会自动按 8 MHz 反算。

### 8.5 采样点填了 87.5%，实际显示别的值

8 MHz 时钟下无法精确命中某些采样点组合时，程序会选最接近的解并标注实际值。若必须精确，勾选「手动 BRP/SEG」直接填 brp/tseg1/tseg2。

### 8.6 导入 ASC 后一帧都没识别

旧版本只认 `ID#DATA` 写法。v3.2 起同时支持 `Rx d 8` 格式。如果仍然失败，把该文件前几行发出来，可能是其他变体。

### 8.7 UDS 提示「通道未连接」

UDS 窗口复用监控页的通道。先去「监控」页连接通道，再打开 UDS 窗口。

### 8.8 UDS 请求安全访问失败，返回 7F 27 35

Key 算法是示例值，见 7.4。

### 8.9 配置文件在哪

`%LOCALAPPDATA%\BusLens\config.json`

只记一项：上次打开的 DBC 路径。删掉它不影响使用，只是下次启动不自动加载 DBC。

早期版本把配置写在 exe 同级 `.dbc_parser_config.json`，v3.2 会自动迁移并只读新位置。
